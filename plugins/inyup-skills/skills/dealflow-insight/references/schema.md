# 관찰 DB 스키마 (`observations.json`, schema_version 1.0)

관찰 1건 = **딜 문서에 기재된 실측치 하나**. 딜 1건이 관찰 여러 개를 낳는 것이 정상이다(한 IDM에서 원가 관찰 1건 + 확산속도 관찰 1건). 반대로 딜 1건에서 숫자가 하나도 안 나오면 관찰이 0건일 수도 있다 — 그게 정직한 결과다.

> 이 스킬 폴더는 public 저장소다. **이 문서에 딜 회사명·실측 수치를 예시로 넣지 않는다.**

## 필드

| 필드 | 필수 | 내용 |
|---|---|---|
| `obs_id` | ● | `OBS-001` 형식. 한 번 부여하면 재사용·재번호 금지 (딥다이브 산출물이 이 ID를 인용한다) |
| `출처` | ● | 딜·문서명 (`〇〇〇 IDM`, `구글시트 아이디어 '〇〇〇'`) |
| `출처유형` | ● | `IDM` / `시트-소싱딜` / `시트-컴퍼니빌딩` / `시트-아이디어` |
| `일자` | ● | `2026-03` 또는 `2026-02~2026-07` |
| `일자정밀도` | ● | `일` / `월` / `테마범위` |
| `테마` | ● | 시드 맵의 테마 카드명 |
| `유형` | ● | `원가` / `마진` / `지불의사` / `확산속도` / `채널` / `기타` |
| `실측치` | ● | **숫자를 그대로.** 반올림·환산·해석을 섞지 않는다 |
| `수치` | | 기계 판독용 숫자. 문서에 모호함이 없을 때만 채운다 |
| `관찰시장` | ● | `KR` / `US` / `글로벌` — 이 숫자가 **어디서 측정됐나** |
| `시장유효성` | ● | 아래 표 — 이 관찰을 **어느 시장 상장사의 가정 검증에 쓸 수 있나** |
| `신뢰도` | ● | `실측` / `인용` / `정성` |
| `사용처` | ● | `Q1`~`Q7` / `진위판별` / `역방향경보`. 없으면 빈 배열 |
| `함의` | ● | 이 관찰이 상장사 분석에서 무엇을 검증·반박하는가 (1~3문장) |
| `연결_밸류체인` | ● | 후보 종목. `{이름, 시장, 역할, 검증}`. **`검증` 값은 항상 `검증 필요`를 유지한다** |
| `키워드` | ● | lookup 매칭용. 종목명·제품·소재·채널·현상 단어를 넉넉히 |
| `역방향` | ● | 이 관찰이 상장사 리스크(파괴·채널 전환) 경고면 `true` |
| `note` | | 한계·미확인 사항. 확인이 필요한 것을 숨기지 말고 여기에 남긴다 |

`신선도`는 저장하지 않는다 — `일자`에서 조회 시점에 계산한다(신선 ≤6개월 / 유효 7~18개월 / 노후 18개월+).

## `관찰시장`과 `시장유효성`을 분리하는 이유

지리적 비대칭을 정확히 운용하려면 두 질문이 분리돼야 한다.

- **어디서 측정됐나**(`관찰시장`) — 사실
- **어디에 쓸 수 있나**(`시장유효성`) — 판단

미국 아마존 매대를 관찰했지만(관찰시장 US) 그 수요를 먹는 것은 한국 ODM일 수 있다(시장유효성 양쪽). 반대로 한국에서 관찰한 AI 네오펌은(관찰시장 KR) 미국이 선행 시장이다(시장유효성 US선행-KR도착중). 한 필드로 뭉치면 이 구분이 사라지고, 그 순간 "한국 딜 = 한국 주식"이라는 기계적 이식이 시작된다.

| `시장유효성` | 의미 | KR 종목 조회 시 | US 종목 조회 시 |
|---|---|---|---|
| `KR` | 한국 상장사 가정 검증에만 유효 | 예 | 주의 |
| `US` | 미국·유럽 상장사에만 유효 | 주의 | 예 |
| `양쪽` | 원가 구조 등 시장 무관 | 예 | 예 |
| `KR실패-US유효` | 국내에선 안 됐지만 미국에선 유효 | **금지** (반례로만) | 예 |
| `US선행-KR도착중` | 미국이 선행, 한국은 도착 초기 — **매매 대상은 미장** | 주의 (시차 명시) | 예 |

`주의`는 "쓰지 마라"가 아니라 **"시장 차이를 문장에 적어라"**는 뜻이다. `금지`는 지지 근거로 쓰지 말라는 뜻이고, 반례("한국에선 실패했다")로는 쓸 수 있다.

## `신뢰도` 판정

| 값 | 기준 | 쓸 수 있는 곳 |
|---|---|---|
| `실측` | 딜 회사가 직접 만든 숫자 (자사 원가·마진·수주·매출) | 전부. 컨센서스 반박의 주 재료 |
| `인용` | 딜 문서가 인용한 3자 수치 (M&A 배수, 경쟁사 밸류, 시장 규모) | 앵커·배경. **밸류에이션 근거로 쓰지 말 것** — 인용 시점이 과거다 |
| `정성` | 숫자 없는 관찰 (방향·의지·반복 관찰) | Q4(파급 사슬 위치)까지. **단독으로 변별점(Q1) 근거 불가** |

이 구분이 이 DB의 핵심 방어선이다. `정성` 관찰을 `실측`처럼 쓰면 "섹터가 겹친다"를 엣지라고 부르는 것과 같아진다.

## 관찰을 추가할 때의 판정 순서

1. **숫자가 있나?** 없으면 `신뢰도: 정성`으로 기록하되, 함의에 "단독 사용 불가"를 적는다.
2. **그 숫자를 딜 회사가 만들었나, 어디서 인용했나?** → `실측` vs `인용`
3. **어디서 측정됐나?** → `관찰시장`
4. **다른 시장 종목에 이식해도 되나?** 원가·제조 구조는 대개 `양쪽`, 소비자 지불의사·채널·규제는 대개 한쪽. 확신이 없으면 좁게 잡는다(`양쪽`보다 `KR`).
5. **이게 상장사에 나쁜 소식인가?** → `역방향: true`. 순방향·역방향 양쪽이면 `true`로 두고 함의에 둘 다 쓴다(OBS-026 TIC가 그런 경우다).
6. **어떤 종목의 어떤 가정을 건드리나?** → `함의`. 여기가 비면 그 관찰은 lookup에서 쓸모가 없다.

## 하지 말 것

- **티커 코드를 기억으로 채우지 않는다.** `연결_밸류체인`에는 회사명만 넣는다. 티커는 딥다이브 시점에 실제 소스에서 해석한다 — 6자리 코드 한 글자가 틀리면 전혀 다른 회사가 되고, 조용히 틀린다.
- **`검증 필요` 라벨을 지우지 않는다.** 딥다이브를 통과했다는 사실은 이 DB가 아니라 딥다이브 산출물에 기록된다.
- **테마를 늘리지 않는다.** 관찰 3건 미만이면 기존 `기타 관찰` 테마에 넣는다.
- **`실측치`에 해석을 섞지 않는다.** "부자재가 비싸다"가 아니라 "부자재 __원 · 내용물 __원"처럼 문서에 적힌 숫자를 그대로 옮긴다. 해석은 `함의`에 쓴다.
