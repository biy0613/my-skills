# refresh — 갱신 절차와 소스 접근

분기 1회 또는 사용자 요청 시 실행한다. 목표는 **변경분만 정확히 늘리는 것**이지 맵을 다시 쓰는 것이 아니다.

## 0. 식별자는 이 문서에 없다

이 스킬 폴더는 **public GitHub 저장소**다. 노션 워크스페이스 경로·구글 시트 ID·수집 대상 명단 같은 식별자는 여기에 적지 않는다. 데이터 폴더의 **`dealflow-sources.local.md`**를 읽어서 얻는다.

그 파일이 없으면 사용자에게 요청한다. **식별자를 기억이나 추측으로 채워 넣지 않는다** — 틀린 시트를 읽고도 정상 동작한 것처럼 보이는 것이 최악이다.

## 1. 모드 판정 (항상 먼저)

MCP 도구 이름에는 세션마다 달라지는 서버 해시가 붙는다(`mcp__<hash>__notion-search`). **이름을 외워 쓰지 말고 ToolSearch로 접미사를 찾아 로드한다.**

```
ToolSearch: "select:notion-search,notion-fetch"
ToolSearch: "+drive search_files read_file_content"
```

| 모드 | 조건 | 할 수 있는 것 |
|---|---|---|
| **A — 소스 직결** | 노션 MCP + 구글 드라이브 MCP가 응답 | 신규 IDM·시트 행 자동 수집 |
| **B — 시드 전용** | 위가 없거나 인증 필요 | 사용자가 폴더에 넣어준 export(시트 xlsx, 신규 IDM 텍스트)만으로 운용 |

**모드 B인데 갱신 원료가 없으면 "갱신 불가, 파일 필요"라고 말하고 끝낸다.** 다른 경로를 임의로 시도하지 않는다.

## 2. 노션 — 읽기 전용

수집 위치·필터·대상은 `dealflow-sources.local.md`를 따른다.

```
notion-search { query: "IDM", query_type: "internal", page_size: 25, max_highlight_length: 0 }
→ 결과의 id로 notion-fetch 해서 본문을 읽는다
```

작성자 필터는 `filters.created_by_user_ids`로 건다. 사용자 ID는 `notion-search { query_type: "user", query: "<이름>" }`으로 먼저 찾는다.

**쓰기 계열 도구는 호출하지 않는다.** `notion-create-*`, `notion-update-*`, `notion-move-*`, `notion-duplicate-page`, `notion-create-comment` 전부 금지. 조회만 한다.

### 이미 밟아본 함정 — 반복하지 말 것

1. **검색 인덱스에 안 잡히는 IDM이 6건 있다.** 명단은 로컬 식별자 파일에 있다. 검색으로 못 찾는 것이 정상이니 **"없는 문서"로 결론 내지 말고 사용자에게 링크를 요청**한다. 이걸 모르면 "커버리지 완료"라고 잘못 보고하게 된다.
2. **검색 결과의 `timestamp`는 작성일이 아니라 최종 수정일일 수 있다.** 관찰의 `일자`는 **시트의 주간 공유일을 우선**한다. 노션 timestamp를 일자로 쓰면 오래된 딜이 최신 관찰로 둔갑하고 신선도 판정이 통째로 틀어진다.
3. **검색 백엔드가 두 종류다.** 응답의 `type`이 `workspace_search`면 워크스페이스 전용 검색이 돌아간 것이고, 위 1번의 누락은 여기서 발생한다. 의미 검색이 필요하면 `content_search_mode: "ai_search"`를 명시한다.

## 3. 구글 시트 — 읽기 전용

파일 ID·표 구성·컬럼은 `dealflow-sources.local.md`를 따른다.

4. **시트를 텍스트로 읽으면 `(문서 링크)` 셀의 하이퍼링크 URL이 나오지 않는다.** 셀 자체에는 항목명·일자·담당자만 있다. 링크 문서 본문이 필요하면 Sheets API의 링크 추출을 쓰거나 **사용자에게 요청**한다. 이걸 모르고 "시트에 내용이 없다"고 결론 내면 안 된다 — 내용은 링크 너머에 있다.
5. **수집 범위 확장은 사용자 승인이 필요하다.** 기본값과 확장 조건은 로컬 식별자 파일에 적혀 있다.
6. **드라이브 쓰기 도구 금지.** `create_file`, `copy_file`, `create_folder` 등은 호출하지 않는다.

## 4. 관찰 추출

수집한 문서에서 **숫자를 찾는다.** 사업 설명·시장 전망·팀 소개는 관찰이 아니다. 추출 대상은 이 다섯 가지다.

| 유형 | 무엇을 찾나 |
|---|---|
| 원가 | 부품·원료·인건비 단가, 단가 구조 분해, 원가 하락률 |
| 마진 | GM·공헌이익률, 기존 방식 대비 마진 차이 |
| 지불의사 | 실제 구매·선주문·판매가, 시장별 판매가 차이 |
| 확산속도 | 초기 매출 램프업, 창업 후 개월 수 대비 성과, 채널 확장 속도 |
| 채널 | 어느 채널이 열리고 닫히는가, 유통이 먼저 접근했는가 |

스키마·판정 기준은 `schema.md`를 따른다. 새 `obs_id`는 기존 최대값 +1부터 부여하고 **기존 ID는 재사용하지 않는다** — 딥다이브 산출물이 이 ID를 인용하고 있다.

## 5. 갱신과 보고

1. `observations.json`의 `db_version`을 `v2`, `v3`으로 올리고 `생성일`을 갱신
2. 갱신 전 파일을 `observations-v{이전}.json`으로 백업 (덮어쓰기 전에)
3. `python scripts/render_table.py`로 표를 다시 생성
4. **변경분만** 보고한다:

```
[관찰 DB v1 → v2] YYYY-MM-DD
· 신규 관찰 n건 (테마별 내역)
· 승격된 테마: (관찰 3건 이상 반복된 것만)
· 시장 유효성 변경: OBS-0xx  KR → US선행-KR도착중  (사유)
· 여전히 미확보: (미포착 IDM / 미승인 확장 범위)
내부 분석용 · 투자 권유 아님
```

전체 맵을 다시 출력하지 않는다. 사용자는 이미 이전 버전을 읽었다.

**새 테마는 관찰 3건 이상 반복될 때만 카드로 승격한다.** 2건이면 흥미로운 우연이고, 3건이면 패턴이다.

## 6. 시드 맵(`dealflow-insight-map-v1.md`)의 취급

읽기 전용이다. 맵은 서술본이고 정본은 `observations.json`이다. 맵을 갱신해야 할 만큼 큰 변화(테마 카드 신설·삭제)가 생기면 **사용자에게 새 버전 작성 여부를 묻는다** — 임의로 `-v2.md`를 만들지 않는다.

## 7. 알려진 데이터 한계 (v1 기준, 우선 교정 대상)

- **개별 딜 일자가 없다.** 시드 맵이 테마 단위 기간만 기록해서 대부분 관찰이 `일자정밀도: 테마범위`이고, 신선도를 범위 종료월로 계산하므로 **실제보다 신선하게 보인다.** 첫 refresh에서 노션·시트의 주간 공유일로 교정하는 것이 최우선 작업이다.
- 관찰 중 일부는 판매 채널(국내/해외)이 맵에 없어 `시장유효성`을 보수적으로 좁게 잡아 두었다. 각 관찰의 `note` 필드를 확인해 원문에서 교정한다.
