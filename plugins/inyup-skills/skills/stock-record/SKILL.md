# 종목 기록 (stock-record)

원장: `%USERPROFILE%\OneDrive\바탕 화면\클로드실습\주식\트레이딩 기록\포트폴리오기록.xlsx`
(경로를 바꾸려면 환경변수 `STOCK_PORTFOLIO_XLSX` 로 덮어쓴다)
설계 근거: `주식/투자체크포인트_템플릿.md`

> **이 문서는 공개 저장소에 있다.** 아래 예시의 종목·수량·단가는 전부 **가상 값**이다.
> 실제 보유 내역·논지·잔고는 이 저장소에 절대 적지 않는다. 기록은 전부 저장소 밖 xlsx로 간다.
> payload JSON은 **임시 폴더**에 쓴다. 스킬 폴더 안에 쓰면 자동 커밋으로 GitHub에 올라간다.

## 0. 이 스킬의 원칙 — 어길 것 같으면 먼저 지적한다

1. **진입 기록은 매수 주문 전에 작성한다.** 이미 사고 나서 적는 것이면 그렇다고 말하고,
   기록에 "사후 작성"이라고 남긴다. 사후 작성은 기록이 아니라 합리화다.
2. **체결 후 수정 금지.** 진입 기록이 이미 있는 종목에 다시 진입 기록을 넣으면 스크립트가
   거부한다. 생각이 바뀐 것이면 **보유점검**으로 남긴다.
3. **게이트 판정을 사용자 대신 완화하지 않는다.** X가 나오면 X라고 적는다.
   사용자가 그래도 진행하겠다고 하면 따르되 `규칙 이탈`로 명시한다.
4. 투자 판단 자체(사라/팔아라)는 하지 않는다. 항목을 묻고, 빠진 곳을 지적하고, 기록한다.
5. **★ 문항을 물을 때는 항상 전문을 함께 띄운다.** 사용자가 2026-08-02에 명시적으로
   요청한 사항이다. "B 강제트리거 몇 개 켜졌나요?" 처럼 번호만 묻지 않는다.
   **6개 문항 전문을 그대로 나열하고 하나씩 O/X를 받는다.** 매도 유형도 마찬가지로
   ①~⑤ 후보와 각 요건을 매번 보여준 뒤 고르게 한다. 진입 하드게이트 6, 회수 A 보류게이트 7도
   같다. 사용자는 문항을 외우고 있지 않으므로, 보여주지 않으면 판정 자체가 불가능하다.
   문항 전문은 아래 5절에 있고, 스크립트로도 뽑을 수 있다:
   `python "$env:USERPROFILE\.claude\skills\stock-record\scripts\record.py" --gates`
6. **★ 격언을 게이트와 함께 띄운다.** 원장 `[격언]` 시트에 사용자가 신뢰하는 투자자의 원칙이
   들어 있고, 각 격언은 게이트 문항 번호에 연결돼 있다. 게이트를 띄울 때 그 문항에 걸린 격언도
   같이 읽어준다. 그리고 사용자가 격언의 **[내가 어길 때 나오는 말·행동]** 에 해당하는 말을 하면
   **"알겠습니다" 하고 넘어가지 말고 그 격언을 인용해 먼저 지적한 뒤 진행 여부를 확인한다.**
   2026-08-12 사용자 상시 요청이다. 지적한 건은 ② 제지 기록에 남긴다 (7절).

## 1. 무엇을 기록할지 확정

사용자 말에서 **종목**과 **단계**를 뽑는다. 둘 중 하나라도 불분명하면 묻는다.

| 사용자가 하는 말 | 단계 |
|---|---|
| "샀어", "매수했어", "들어갔어", "진입" | 진입 |
| "점검", "분기 점검", "실적 나왔어", "다시 봐야겠어" | 보유점검 |
| "팔았어", "정리했어", "손절", "익절" | 회수 |
| "팔았어야 했는데 안 팔았어", "트리거 켜졌는데 홀드" | 홀드 |
| "그때 판 거 지금 어떻게 됐지", "D+90" | 사후추적 |

새 종목이면 시트가 자동 생성되므로 미리 만들 필요 없다.

## 2. ★ 먼저 "엑셀의 어느 칸을 채워야 하는지" 를 띄운다

**종목·단계가 정해지면 다른 말을 하기 전에 이것부터 실행한다.**

```bash
python "$env:USERPROFILE\.claude\skills\stock-record\scripts\record.py" --template --stock <종목명> --stage <단계>
```

출력은 **그 종목 시트의 실제 셀 좌표**와 함께 나온다. 이미 채워진 칸과 빈 칸이 분리돼 있다.

```
■ 삼성전자 · 진입  —  시트 [삼성전자]
   빈 자리 1 / 전체 23

── 채워야 할 자리 1개 ──
    C37  손절하지 않는 경우  :    ← 예: 시장 전체 조정이고 위 사실 기준 미발생

── 이미 적힌 자리 22개 (고치려면 그대로 다시 주세요) ──
    C21  핵심 논지 (한 문장)  : 돈을 매우 많이 버는 기업인데 현재 선행 PER 4배…
```

**이 출력을 그대로 채팅에 붙여넣는다.** 요약하거나 항목 이름을 바꾸지 않는다 —
사용자는 이 목록을 보고 바로 답을 적는다. 셀 좌표가 있어야 엑셀에서 직접 고칠 수도 있다.

`references/templates.md` 는 각 항목이 무엇을 묻는지 설명이 필요할 때만 참고한다.
**질문의 1차 소스는 `--template` 출력이다.** 사람이 옮겨 적은 목록은 실제 시트와 어긋날 수 있다.

### ★ 진행 순서 — 사용자가 2026-08-02에 지정한 방식

**1단계. 게이트를 O/X로 받는다**

진입이면 하드게이트 6, 회수면 A 7 + B 6 문항 **전문**을 아래 5절 형식 그대로 띄운다.
사용자는 `[O]` `[X]` 로 답한다. 여기서는 서술 항목을 함께 묻지 않는다.

문항을 띄우기 **전에** 이 단계의 격언을 먼저 뽑아 함께 붙여넣는다:

```bash
python "$env:USERPROFILE\.claude\skills\stock-record\scripts\record.py" --maxims --stage <단계>
```

출력을 그대로 붙여넣고, 게이트 문항 옆에 걸린 격언 ID를 표시한다.
`--gates` 출력의 `격언_연결` 이 **문항 코드 → 격언** 대응표다
(`E1~E6` 진입 하드게이트 / `A1~A7` 회수 A / `B1~B6` 회수 B / `T1~T6` 매도 유형).
문항 하나에 걸린 격언만 보려면 `--maxims --gate A5` 처럼 코드를 준다.

격언이 없거나 `[격언]` 시트가 없으면 스크립트가 그렇게 알려주고, 기록은 그대로 진행한다.

**2단계. 엑셀 행을 하나씩 직접 물어본다**

```bash
python "$env:USERPROFILE\.claude\skills\stock-record\scripts\record.py" --questions --stock <종목명> --stage <단계>
```

진입이면 **C21~C39** 19개 항목이 번호 매긴 질문으로 나온다. 이 출력을 **그대로 붙여넣는다.**
라벨만 나열하지 않고 질문 문장이 함께 나오므로 사용자가 바로 답을 적을 수 있다.

```
 1. [C21] 핵심 논지 (한 문장)
    이 종목을 사는 이유를 **한 문장**으로 말하면?
    →
```

**C17~C20(기록일 · 하드게이트 통과 · 미통과 항목 · 규칙 이탈 여부)은 묻지 않는다.**
1단계 게이트 답변에서 자동으로 만들어 채운다. 회수의 A/B 개수도 마찬가지다.

**3단계. 답을 payload로 만들어 기록하고, 남은 빈 칸을 보고한다.**

> `--template` 은 셀 좌표와 현재 값을 점검할 때 쓴다(이미 적힌 칸 확인, 부분 수정).
> **사용자에게 물을 때는 `--questions` 를 쓴다.**

사용자가 "대충 적어줘" 하더라도 **핵심 논지 · 반대 논지 · 손절 조건(사실+가격) 네 가지는
반드시 받는다.** 이 넷이 비면 나중에 회수 판단의 근거가 없어서 기록 전체가 무용해진다.

빈 항목이 있어도 기록은 진행한다. 기록 후 `시트에_남은_빈_항목` 을 그대로 보고한다.
이 값은 payload가 아니라 **시트를 다시 읽어 판정**하므로, 부분 갱신을 해도 정확하다.

## 3. 엑셀에 반영

payload를 만들어 `scripts/record.py` 에 넘긴다.

```bash
python "$env:USERPROFILE\.claude\skills\stock-record\scripts\record.py" --input payload.json
```

payload는 임시 폴더에 UTF-8로 쓴다. 형식:

```json
{
  "종목명": "ACME",
  "단계": "진입",
  "마스터": {
    "티커": "ACME", "시장": "NASDAQ", "통화": "USD",
    "수량": 10, "평균단가": 50.0,
    "진입일": "2026-01-01", "목표비중": 0.05,
    "손절선": 35, "익절목표": 80
  },
  "데이터": { "핵심 논지 (한 문장)": "...", "반대 논지 (2개 이상)": "..." }
}
```

- `종목명`은 **[보유종목] 마스터의 종목명과 정확히 같아야** 한다. 종목 시트의 요약 수식이
  이 이름으로 마스터를 찾는다. 새 종목이면 아무 이름이나 정하되 이후 계속 같은 이름을 쓴다.
- `마스터`는 선택이다. 수량·평단이 바뀌었을 때만 넣는다.
- 필드 이름이 헷갈리면 먼저 확인한다: `python record.py --fields 진입`
- 단계별 자동 처리: 진입 → 상태=보유·진입일 기록 / 보유점검 → 최근점검일 갱신 /
  회수 → 상태=청산.

## 4. 보고

스크립트 출력의 `시트에_남은_빈_항목`을 사용자에게 그대로 전달하고, 그중 **핵심 논지·
반대 논지·손절 조건**이 비어 있으면 따로 짚는다. 나머지는 나중에 채워도 되는 항목이다.
남은 항목이 많으면 `--template` 을 다시 돌려 붙여넣는 편이 낫다.

스크립트 출력에 `이_단계의_격언` 이 있으면 그것도 함께 전달한다. 기록이 끝난 뒤가
격언을 다시 읽기 좋은 자리다 — 방금 적은 근거가 격언과 어긋나 있으면 여기서 잡힌다.

기록 후 다음 행동을 한 줄로 제안한다:
- 진입 → 새 종목이면 그 종목 전담 X 계정을 찾아서 제안한다 (사용자 상시 요청)
- 보유점검 → 결론이 `회수검토`면 회수 게이트를 이어서 돌릴지 묻는다
- 회수 → 사후추적 **1달 후 / 2달 후 / 반년 후** 날짜를 계산해 알려준다

## 5. 게이트 판정표 — **묻을 때마다 전문을 그대로 띄운다**

판정은 사용자가 한다. 나는 문항을 보여주고, 답을 받고, 빠진 곳을 지적하고, 기록한다.

문항 뒤의 `[Mxx]` 는 그 문항에 걸린 격언이다. **대응표는 이 문서가 아니라 `[격언]` 시트가
소스 오브 트루스다** — 아래 표기는 2026-08-12 기준이고, 격언이 추가되면 달라진다.
실제 대응은 `--gates` 출력의 `격언_연결` 로 확인한다.

### 진입 하드게이트 6 — 하나라도 X면 매수 보류

1. 실적 발표를 1회 이상 통과하며 관찰했는가 (최소 1개월)
2. 이 종목을 한 문장으로 설명할 수 있는가  `[M02]`
3. 반대 논지를 2개 이상 적을 수 있는가
4. 손절 조건을 가격 + 사실 양쪽으로 숫자화했는가
5. 포지션 크기가 사전 규칙 내인가 (**비중 상한 30% + 최대 허용 손실 30%**)  `[M01]`
6. 사는 이유가 급등·뉴스·손실 복구가 아닌가 (24시간 쿨다운)  `[M03]` `[M05]`

### 회수 A 보류게이트 7 — 하나라도 X면 매도 보류

1. 매도 유형을 하나로 특정했는가
2. 진입 시 적어둔 손절/익절 조건 중 실제로 발동한 항목이 있는가  `[M06]`
3. 매도 이유가 주가가 아니라 사실로 설명되는가
4. 이 결정을 어제도 똑같이 했을 것인가 (24h 쿨다운)  `[M08]`
5. 오늘 안 갖고 있다면 이 가격에 사지 않을 것인가  `[M06]`
6. 매도 후 2배 더 올라도 판단이 옳았다고 말할 근거가 있는가
7. 지금 감정이 공포·지루함·본전 심리가 아닌가  `[M07]` `[M08]`

### 회수 B 강제트리거 6 — 하나라도 O면 매도가 원칙

1. 진입 시 적은 사실 기준(thesis break) 중 하나 이상 발생
2. 가정 3개 중 2개 이상 반증
3. 가격 손절선 이탈 + "손절하지 않는 경우"에 해당하지 않음
4. 경영진 신뢰 훼손 (회계 이슈, 공시 번복, 내부자 대량 매도, 갑작스러운 CFO 사임)
5. 논지 드리프트 — 새 이유로는 진입 게이트를 통과 못 함
6. 비중 상한 초과 상태로 3개월 이상 방치

**B가 켜졌는데 A가 X면 B가 우선한다.** A는 충동 매도를 막는 장치지 강제 매도를 무르는
장치가 아니다. B가 켜졌는데 팔지 않기로 했다면 **반드시 `홀드` 단계로 기록한다.**
매도만 기록하고 안 판 것을 남기지 않으면 가장 비싼 실수가 기록에 안 남는다.

> 회수 단계를 시작하면 **A 7문항과 B 6문항을 먼저 전부 화면에 띄우고** 하나씩 답을 받는다.
> 개수만 물어보면 사용자가 무엇을 세는지 모른다.

### 매도 유형 6 — **후보 6개와 요건을 매번 보여준 뒤 고르게 한다**

| 유형 | 요건 | 흔한 오분류 |
|---|---|---|
| ①논지훼손 | 사실 기준·가정이 실제로 반증됨. 가격 하락은 요건이 아님 | 사실은 그대로인데 주가만 빠진 것 |
| ②목표달성 | 익절 사실 기준 도달 또는 목표가 도달 + 남은 논지 없음 | 목표 근처에서 불안해서 파는 것 |
| ③교체 | 새 후보가 진입 게이트 통과 + 세금·비용 차감 후에도 우위 | 손실 회피를 "더 좋은 종목"으로 포장 |
| ④리스크관리 `[M07]` | 논지는 유효하나 비중 상한 초과·유동성 문제. 부분 매도가 원칙 | 전량 매도해놓고 ④라고 적음 |
| ⑤현금필요 | 투자 판단과 무관한 실생활 자금 수요 | 시장 전망이 나빠서 파는 것 |
| **⑥타이밍** `[M09]` | **논지는 그대로인데 가격·시점 판단으로 매도. 재매수 의도가 있는 매도** | **재매수 조건 없이 ⑥이라 적기 — 그건 그냥 매도다** |

**①~⑤는 전부 "논지에 무슨 일이 생겼나"를 묻는다. ⑥만 논지가 그대로인 채
"잠깐 나갔다 들어온다"는 매도다.** 2026-08-08에 사용자 요청으로 추가했다 —
그 전까지 실제 매도 4건이 ①~⑤ 어디에도 안 맞아 전부 빈칸이 됐기 때문이다.

**⑥을 고를 때 반드시 함께 받을 것 (남용 방지 장치)**

1. **재매수 조건을 숫자로** — 가격 또는 시점. "급락하면", "하단에서" 같은 말은 판정이 안 된다.
   조건이 없으면 ⑥이 아니라 그냥 매도다.
2. **사후추적에서 실제 재매수 여부를 확인** — 1달 후 / 2달 후 / 반년 후에
   "다시 샀는가"를 적는다. 안 샀으면 타이밍 판단이 아니라 이탈이었던 것이다.

이 둘이 붙어야 ⑥이 변명이 아니라 **검증 가능한 주장**이 된다.
⑥이 몇 건이고 합산 손익이 얼마인지 집계할 수 있어야 "타이밍 매매가 실제로 돈이 됐는가"를
나중에 답할 수 있다.

## 6. 워크북 구조 (고칠 때 알아야 할 것)

| 시트 | 역할 |
|---|---|
| 대시보드 | KPI + 평가액 스냅샷 시계열 + 총자산 차트. **전부 수식** |
| 보유종목 | 종목 마스터. **수량·평균단가는 여기서만 고친다** |
| 시세기록 | 날짜×종목 주당단가 원장. append 전용. 마지막 행이 현재가로 잡힌다 |
| 설정 | USD/KRW 환율, 비중 상한 |
| 격언 | 사용자가 신뢰하는 투자자의 원칙 + 제지 기록 + 원문 보관. **7절 참조** |
| 종목 시트 | 진입 / 보유점검 / 회수 / 홀드 / 사후추적 |

종목 시트 A열의 회색 `#ENTRY` `#REVIEW` 같은 글자는 **스크립트가 기록 위치를 찾는 앵커다.
지우면 자동 기록이 멈춘다.** 사용자가 행을 끼워 넣거나 지워도 앵커만 살아 있으면 동작한다.
[격언] 시트도 같은 방식이다 (`#MAXIM` `#INVOKE` `#SOURCE`).

평가액 갱신은 이 스킬이 아니라 **`stock-price`** 스킬이 한다.

## 7. 격언 — 제지하고, 제지한 것을 남긴다

`[격언]` 시트는 세 블록이다. **격언 본문은 이 저장소에 두지 않는다** — 여기는 공개 저장소이고,
격언과 그 위반 신호는 사용자 개인의 판단 습관이다. `scripts/maxims.py` 는 읽기만 한다.

| 앵커 | 블록 | 내용 |
|---|---|---|
| `#MAXIM` | ① 격언 원장 | ID · 격언 한 줄 · 뜻 · **위반 신호** · 적용 단계 · **게이트 코드** · 출처 · 원문 |
| `#INVOKE` | ② 제지 기록 | 제지한 날 · 격언 ID · 하려던 행동 · 짚은 것 · 결정 · 결과 |
| `#SOURCE` | ③ 원문 보관 | 사용자가 붙여넣은 원문 전문 |

### 제지 절차

1. 사용자의 말·행동이 어느 격언의 **[내가 어길 때 나오는 말·행동]** 에 걸리는지 본다.
2. **격언 한 줄 + 원문 문장을 인용하고, 지금 하려는 행동의 어느 부분이 걸리는지 한 문장으로
   짚는다.** 설교하지 않는다. 판단 자체(사라/팔아라)는 여전히 하지 않는다.
3. **지적은 하되 사용자가 듣고도 진행하겠다면 그 결정을 따른다.** 이 스킬 0절 3번과 같다.
4. 제지한 건은 ② 에 남긴다. 수용했든 강행했든 남긴다 — 남기지 않으면 나중에
   "제지가 실제로 돈이 됐는가"를 답할 수 없다.

```bash
python "$env:USERPROFILE\.claude\skills\stock-record\scripts\record.py" --invoke --input invoke.json
```

```json
{
  "일시": "2026-08-12 15:40",
  "격언ID": "M05",
  "행동": "급등한 종목을 지금이라도 사려 함",
  "짚은것": "만회 매수. 진입 하드게이트 6 미통과 + 24시간 쿨다운 없음",
  "결정": "수용 — 안 함",
  "결과": ""
}
```

`결정` 은 `수용 — 안 함` / `조정 — 크기·시점 변경` / `강행 — 그대로 진행` 셋 중 하나다
(시트에 드롭다운으로 걸려 있다). **강행이면 그 사실을 그대로 적는다.**
결과가 실제 손실로 이어졌으면 `[레슨런]` 시트에도 옮겨 적는다 — 격언 시트는 원칙,
레슨런은 사건이다.

### 새 격언이 들어올 때

사용자가 격언을 붙여넣으면 **원칙 단위로 쪼개** ① 에 M10, M11 … 로 잇고, 원문은 ③ 에
통째로 남긴다. 한 행은 "한 번에 하나씩 어길 수 있는" 크기여야 판정이 된다.
**[내가 어길 때 나오는 말·행동] · [적용 단계] · [게이트 코드] 세 칸을 반드시 채운다** —
비면 그 격언은 기록 작업 중에 자동으로 뜨지 않는다.
